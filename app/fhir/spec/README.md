# FHIR R4 spec artifacts

`fhir.schema.json` — the official HL7-published JSON Schema for FHIR **R4**
(confirmed: `"id": "http://hl7.org/fhir/json-schema/4.0"`), sourced from the
"definitions" download on hl7.org/fhir/R4/downloads.html. Not hand-written or
generated by this project — copied in as-is.

`profiles-resources.json` — the same download's `StructureDefinition` bundle
for every base R4 resource (147 entries where `kind == "resource"` and
`derivation == "specialization"`, confirmed directly against the file —
matches R4's known base resource count). Also not hand-written — copied in
as-is. This is `app/fhir_profile/seed_base_profiles.py`'s one and only
source for seeding `fhir_profile`'s `scope_level='base'` rows — every real
base resource gets seeded straight from here, not from individually
hand-copied per-resource files.

## What it's for

The base layer of this project's planned profile validation pipeline (see
`docs/architecture/fhir-profiling-and-extensibility-strategy.md`) — base R4 →
country → organization. Verified directly (see that doc / project history)
against a real JSON Schema validator:

- Enforces structure, required (1..1) fields, primitive-type formats
  (e.g. `positiveInt`), **and required-binding coded values** (e.g.
  `ContactPoint.system`/`use` are real `"enum": [...]` constraints here —
  confirmed better in this respect than the `fhir.resources` Python package,
  which only carries those as metadata, not enforcement).
- Does **not** enforce invariants (`org-1`, `org-2`, `org-3`, and every other
  FHIRPath-expressed `constraint` in the spec) — confirmed empirically: an
  empty `Organization` (no `name`, no `identifier`) validates cleanly against
  this schema. `anyOf` appears 0 times and `oneOf` only twice (both unrelated
  top-level constructs) across the entire 60,000+ line file — invariants are
  never attempted here, for any resource. A separate mechanism (reading
  `StructureDefinition.snapshot.element[].constraint` and evaluating the
  FHIRPath expressions, e.g. via `fhirpathpy`) is still needed for those,
  since not every resource carries the same invariants and some have none at
  all — this is deliberately a later, separate piece of work, not bundled
  into this schema file.

## Updating

If this project ever needs to move to a different FHIR version, replace this
file with the matching `fhir.schema.json` from that version's own
"definitions" download — don't hand-edit it.
